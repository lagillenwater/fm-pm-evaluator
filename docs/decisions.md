- **2026-09-01** (`rung0-assay-reliability`, sixth entry) — §1 gained "What reaches GitHub, and when", answering Lucas's question whether work can stay local or on Alpine before pushing. Partly, and the split is not negotiable in one direction: **code and documents must be pushed**, because `git push` → `ralpine update` → `ralpine submit` is the only sanctioned route to the cluster (§2) and direct copying is refused by the boundary script — so a task branch accumulates code commits from the start, which is fine, since that is the small review surface a reviewer reads anyway. **Everything a run produces stays out of git until promotion**: results land on scratch, are pulled to the working tree, and Verify, Audit and Summarise all run against those local files. The reason is not tidiness — git stores every version of a file whole and forever, so a result table committed, corrected and recommitted three times costs three permanent copies and no later cleanup removes them. Exposure accepted and recorded: between the run and promotion the evidence lives on purgeable scratch and in one working tree, and losing both costs a re-run (about forty minutes with the build cache), not the result, since the pinned tranche plus committed code is the reproduction chain. What it must not cost is a claim without its artifact, which is what the checksum rule and the single promotion-plus-evidence commit prevent.
- **2026-09-01** (`rung0-assay-reliability`, fourth entry) — §1 gained the **reading order** for a pull request description and the **review surface versus generated evidence** definition, at Lucas's direction. Reading order: `summary.ipynb` first (run it, and the finding arrives with its figures), then `design.md` (what the measurement was meant to be), then `audit.md` (where the two are checked against the tree); everything else is reached from those three. The default order is the reverse — a reviewer opens a diff, forms an impression from the code, and reads the finding last — which is the failure this rule addresses. The split itself: the review surface is the task's documents, both notebooks, and `src/`, `scripts/`, `tests/`; generated evidence is result tables, provenance records, parameter files, figures, cluster logs and tranche manifests, committed to be checked mechanically rather than read, and marked `linguist-generated` so it collapses in the diff. A new kind of generated artifact is added to `.gitattributes` in the change that first produces it; the figures directory and provenance records were added there in this change, since the figure rules created a new generated path.
